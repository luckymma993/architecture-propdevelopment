## 2. Какие разделы включены и почему

Компания готовится к первому комплексному аудиту. Главные проблемы из описания:

1. **Нарушен контроль данных.** Клиент регистрируется в нескольких местах без координации, внутренние потоки данных не контролируются, в системах обработки данных нет ограничений доступа. Клиенты видят в личном кабинете чужие ФИО.
2. **Небезопасные API партнёров.** Контракты раскрывают персональные данные, партнёр одной управляющей компании может видеть и менять данные другой.
3. **Риск утечки и нарушения 152-ФЗ.** У конкурента уже была утечка, а соответствие законодательству не проверено.
4. **Процессный разрыв.** Специалист по ИБ один на компанию, после смены руководителей ему передают не все изменения.

Исходя из этого, в лист включены разделы:

| Раздел | Включён | Почему |
| --- | --- | --- |
| I. Управление доступом | полностью | Проблемы 1 и 2 — это ошибки управления доступом: нет минимальных привилегий, нет единого реестра учётных записей, разные Keycloak и AD без централизации. |
| II. Безопасность данных | полностью | Ключевая проблема компании. Нужно проверить классификацию, учёт персональных данных, анонимизацию для хранилища, целостность и Data Governance — без них нельзя запускать BI/ML-продукты. |
| III. Защита инфраструктуры | частично (вопросы 1, 2, 5, 8, 11, 12) | Инфраструктура гибридная: свой ЦОД, приватное и арендованное облако. Включены вопросы о периметре, сегментации и сканировании уязвимостей: от них зависит, можно ли изолировать хранилище и интеграции. Антивирусы и сигнатуры — штатная эксплуатация, с проблемами бизнеса они не связаны. |
| IV. Управление инцидентами | полностью | Руководство боится утечки, как у конкурента. Специалист по ИБ узнаёт об изменениях не всегда, поэтому нужны SIEM, оповещения и план реагирования. |
| V. Специфические аспекты | частично (V.1: 2, 4) | Удалённый доступ и резервные копии в облаке относятся к гибридной инфраструктуре. MDM и физическая безопасность серверных в описании не затронуты, проверять их в первую очередь не нужно. |
| VI. Внешние интеграции и API (добавлен) | полностью | В шаблоне нет раздела про партнёрские API, а это вторая главная проблема компании. Компания собирается развивать партнёрские сервисы, поэтому раздел критичен. |
| VII. Процессы и организация ИБ (добавлен) | полностью | Проблема 4: решения не доходят до специалиста по ИБ. Без процесса согласования изменений технические меры не будут поддерживаться. |

## 4. Выводы

Самые критичные несоответствия, с которых стоит начать:

1. **Контроль доступа партнёров (I.4, I.7, VI.3).** Ввести API Gateway и ABAC-проверку принадлежности данных управляющей компании.
2. **Единый реестр клиентов и учётных записей (I.11, I.14, II.11).** Одна точка регистрации клиента и единый мастер-профиль устранят показ чужих данных в личном кабинете.
3. **Хранилище данных (I.9, II.7, II.13).** Анонимизация или псевдонимизация персональных данных при загрузке, разграничение доступа аналитиков.
4. **Классификация и Data Governance (II.1, II.8, II.9).** Утвердить классификацию из задания 1 и назначить владельцев данных.
5. **Процесс ИБ (IV.3, VII.1).** Обязательное согласование изменений со специалистом по ИБ, план реагирования на инциденты, SIEM.
